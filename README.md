Прототип системы приоритизации генетических вариантов для поиска причин редких наследственных заболеваний

# Приоритизация генетических вариантов

Этот проект представляет собой прототип системы для поиска молекулярной причины редких наследственных заболеваний. Приложение принимает на вход фенотип пациента, описанный в терминах Human Phenotype Ontology (HPO), и список генетических вариантов. На выходе система формирует ранжированный список генов-кандидатов с подробным объяснением каждого вердикта, разделяя подтвержденные данные из баз и вычислительные прогнозы. Проект создан исключительно в исследовательских и образовательных целях и не может рассматриваться как клинический диагноз.

## Инструкция по запуску

Для работы приложения вам понадобится Python версии 3.9 или выше. Сначала скачайте проект. Если у вас установлен Git, откройте терминал и выполните команду для клонирования репозитория:

```bash
git clone https://github.com/LobachArtemiy/Case-3-Hacklab-team.git
cd Case-3-Hacklab-team
```

После того как вы оказались в папке проекта, установите все необходимые зависимости одной командой:
```bash
pip install -r requirements.txt
```

Когда все библиотеки успешно установлены, запустите само приложение:
```bash
streamlit run app.py
```
# Пайплайн
Пайплайн обработки данных состоит из нескольких этапов. Сначала система проводит фильтрацию, отсекая частые варианты, у которых популяционная частота (gnomAD AF) больше или равна 0.01. Затем происходит аннотация: извлекается ген, тип функционального последствия и клиническая значимость. Третий этап — фенотипическое сопоставление. С помощью библиотеки pyhpo вычисляется семантическое сходство между набором терминов пациента и набором терминов, ассоциированных с геном. На четвертом этапе вычисляется итоговый скор как взвешенная сумма четырех признаков: фенотип (вес 0.4), клиническая значимость в ClinVar (вес 0.3), функциональный эффект по VEP (вес 0.2) и редкость варианта (вес 0.1). Наконец, для каждого кандидата формируется объяснение, где четко указано, какой источник данных и с каким весом повлиял на итоговую позицию в рейтинге. Дополнительно реализована задача интерактивного изменения фенотипа: пользователь может добавлять новые симптомы или исключать существующие, и рейтинг пересчитывается в реальном времени.

Логика анализа отображается в виде визуальной воронки, показывающей путь от сырых вариантов до финальных кандидатов. Точность вариантов обеспечивается фильтрацией ложных находок (частых и доброкачественных вариантов) и модулем валидации на development-кейсах с расчетом метрик Top-1 и Top-3 accuracy. Связь с болезнью обосновывается карточками вердиктов с цветовыми бейджами источников (ClinVar, gnomAD, VEP, HPO) и ссылками на соответствующие базы данных. Польза для врача-генетика достигается за счет понятных вердиктов, уровня уверенности, возможности экспорта отчета в CSV и рекомендаций при низкой уверенности.


# Структура проекта
Весь код разделен на две основные части. Файл app.py отвечает за пользовательский интерфейс, отрисовку элементов и взаимодействие с пользователем. Файл prioritizer.py содержит всю вычислительную логику: загрузку данных, фильтрацию, скоринг и формирование вердиктов. В папке .streamlit находится файл конфигурации config.toml с настройками цветовой темы. Подробное описание архитектуры и обоснование выбора инструментов можно найти в файле ARCHITECTURE.md.
